The SDK

The whole client library
is one middleware
and one trick.

// capture the response without touching any route handler
const originalEnd = res.end;

res.end = function (...args) {
  const latencyMs = Date.now() - startTime;

  setImmediate(() => send(payload));  // later tick
  originalEnd.apply(res, args);      // response goes out
};

Never breaks
the host app

Every send is wrapped in try/catch and fails silently. Monitoring must not take down what it monitors.

Bounded
blast radius

A 3-second HTTP timeout, so an unreachable Sendry can't accumulate hanging sockets.

No key,
no-op

Without an API key the middleware returns a pass-through. Safe by default in any environment.

No route changes. No config in
the request path.

Storage design

Why MongoDB and
PostgreSQL?

Not because both are good databases. Because ingestion and analytics are two different workloads.

MongoDB PostgreSQL
holdsRaw API eventsAggregated metrics
shapeFlexible event documentsStructured analytics rows
tuned forHigh-volume writesTime-series reads
lifecycle30-day TTL indexHourly buckets, upserted
grainEvent-level detailDashboard-level rollups
on failureCritical — event is retriedBest-effort — logged, acked
ON CONFLICT (client_id, service_name,
  endpoint, method, time_bucket)
DO UPDATE SET total_hits = ... + EXCLUDED.total_hits

One upsert per event folds it into an existing hourly row, so a 24-hour dashboard query reads buckets instead of scanning raw events.

One store optimised for ingestion.
One optimised for analytics.

Trade-offs

Where this architecture
breaks — and what
V2 does about it.

Today
The problem
V2
idempotencyIn-memory Set, 100k entries, FIFO eviction. Simple and fast.
Doesn't survive a restart, and isn't shared between consumer replicas.
redisSET NX EX, so dedupe is durable and shared.
circuit breakerBreaker state lives in process memory.
Ten replicas means ten opinions about whether the database is healthy.
redisOne shared breaker state across every replica.
throughputA single consumer process with prefetch of 10.
The consumer is the ceiling. Nothing else in the pipeline is.
competing consumersScale replicas horizontally behind the same queue.
NowRabbitMQ → 1 consumer → in-process state
NextRabbitMQ → N consumers → shared Redis state
Knowing the ceiling is worth more
than pretending there isn't one.
